# ROADMAP — 開發路線圖（2026-10-24 版）

這是從現在到「橋譜完成」的**全部順序**。一批 = 一個 PR = 一個 AI session。照批次號依序做，不跳批；每批做完在這裡把 `[ ]` 改成 `[x]` 並寫上 PR 號，同時更新 `docs/NEXT.md`「現在的位置」與 `docs/PRD/README.md` 進度表。task 的細節在 `docs/PRD/e*.md`，開工時只讀該批 task 所在的那一段。

Phase 用字母，**跳過 E**，避免和 Epic 編號（E1…E10）混淆。

**完成的定義**：
- 做完 **Phase A–G** ＝ **M1 社團制度庫＋討論區**：制度集、首頁與個人設定、隊伍與搭檔、制度卡、送審與待確認、社群與討論。這是「每對搭檔有自己的制度、能印制度卡、社團在這裡發公告與討論牌局」的完成點。
- 做完 **Phase H–M** ＝ **M2 學習與叢書**：分級與學習路徑、練習、叢書與電子書、牌桌整合、寫回 Git 與維運。
- **Phase N** ＝ M3 多社團預留，視牌桌 E12 再做。

## 批次之間的原則

1. **同一 Phase 內依批次號做**；不同 Phase 之間只要前提滿足可以交錯（例如 D1 版型檔不依賴任何人，可在 B 進行時先做）。例外：**Phase B 期間不平行開功能**。
2. 一批做不完（超過 3 天）就拆成兩個 PR，批次號加 a／b，不要把半成品合併。
3. 做到一半發現 PRD 的 task 定義有誤，**先在 PR 裡寫明採用的做法**，不要停下來等；真的要人決定的才停（例如視覺稿核准、制度卡欄位、程度名稱）。
4. 每個 Phase 結束跑一次完整回歸：`npm run lint && npm run build && npm test`；視覺與無障礙回歸（`npm run test:browser`）在 CI 的 `browser` job 每次都跑。
5. 牽涉牌桌的批（C2、F4、J 全部、K1、L3）：先在牌桌 repo 開 PR，橋譜 PR 本文寫對應號碼；兩邊的 `protocol.ts` 型別一致才合併。
