## 背景

橋譜的 `responses` 區塊本來就是「叫牌過程 → 叫品 → 意義」，天生是題目。舊 PRD 的 v0.4「測驗模式」要做的就是這件事，而且題目的格式若與牌桌的叫牌題庫（牌桌 E5 AC-5.8 的棘輪）一致，橋譜出的題可以直接餵給機器人評測。

## 目標

- 從制度集的 `responses` 自動生成兩種題：**意義題**（這個叫牌過程下 2♦ 是什麼意思？四選一）與**叫品題**（給一手牌與叫牌過程，該叫什麼？）。
- 依制度集、特約、程度抽題；答完顯示原文段落（深層連結）。
- 錯題本、成績、連續答對；登入後記錄。
- 題目格式與牌桌 `shared/robot` 的題庫一致，可匯出。
- 幹部可修題、停用壞題、手動出題（含牌例）。

## 非目標

- 不做打牌練習（牌桌 E10）。
- 不做排行榜（牌桌 E9 的積分之後再接）。

## 需求

### 功能

- 題目模型（與牌桌對齊）：

  ```ts
  interface Quiz {
    id: string; kind: 'meaning' | 'call'; profileId: string; slug: string; sectionId: string
    auction: Auction; call?: Call; hand?: Hand
    answer: string; choices?: string[]     // meaning：choices 是 4 個意義；call：answer 是叫品
    level: Level; source: 'auto' | 'manual'; disabled?: boolean; note?: string
  }
  ```

- 自動出題：`generateQuizzes(resolvedConventions) → Quiz[]`；意義題的干擾選項取同一表的其他列（不足時取同特約其他表）；叫品題只在 `hand` 區塊或 `note` 有牌例時生成（M2 先做意義題為主）。
- 練習頁 `/practice`：選制度集（預設目前的）、特約（多選）、程度、題數；答題介面（手機優先）；答完顯示段落與「去讀原文」。
- 錯題本 `/practice/mistakes`：答錯的題、再練一次；成績頁：答題數、正確率、依特約的弱點。
- 匯出：`GET /api/book/quizzes?profileId=club&format=table` 回牌桌題庫格式（JSON）；牌桌 CI 可抓。
- 修題：幹部在題目上按「這題有問題」→ 停用或改答案（存成 `manual` 覆寫 `auto`）。

### 非功能

- 自動出題在瀏覽器做（純函式），不打 API；每次練習即時生成並快取。
- 成績只存摘要（每題一列：題 id、對錯、時間），每人上限 5,000 列。

## 設計方向

- 題目生成是純函式、有測試；題目 id 由 `slug/sectionId/blockIndex/rowIndex` 決定，同一題跨裝置一致。
- 答題介面用卡片翻面的感覺（`DESIGN-V2.md`），叫牌過程用既有 `AuctionTable`。
- 牌桌端的題庫格式以牌桌 `e5-t23` 定稿為準，這裡做轉換層 `lib/quizExport.ts`。

## 實作紀錄

- **I1（2026-10-28）**：`src/lib/quiz.ts` 的 `generateQuizzes(conventions, profileId) → { quizzes, skipped }`。題目與選項都是原文逐字：叫牌過程、叫品、意義來自同一列；干擾項先取同表其他列，不足再取同特約其他表，各組依長度接近排序，比較時忽略空白與句尾句號。**不出題的列**（`skipped` 回報原因）：`pending` 的列、在 `pending` 段落（含祖先段落）裡的列、意義空白、叫品空白、意義只有「同上」、湊不滿四個不同意義；這些列的意義也不當干擾項。同一叫牌過程裡同一叫品的其他意義不當干擾項（否則也算對）。`Quiz` 比規格多 `caption`、`trail`（段落標題路徑），`auction` 改為可省略（表沒有叫牌過程時）；`level` 是段落的、否則特約的。內建 22 個特約中 19 個有叫牌表、共 1638 題（總覽、防守信號、制度概念沒有叫牌表）。
- 練習頁 `/practice`（lazy，包在 `ProfiledContent` 裡，所以出題用的是讀者制度集解析後的內容）：制度集下拉（有兩個以上才出現，切換就是頁首的切換）、特約多選（只列有題目的，顯示題數）、程度（全部／入門／進階／高階，未標程度的題只在「全部」）、題數 5／10／20。答完顯示對錯、正解與你的答案、原文叫牌表（可捲動）、「去讀原文」深層連結 `/c/:slug/:sectionId`、下一題；結束頁列答錯的題與原文連結、再練一次。`?c=<slug>` 只選這個特約。入口：首頁「我的制度集」卡的「練習叫牌」、有題目的特約頁「練這個特約」。還沒有成績紀錄（I2）。
- **I2（2026-10-28）**：成績、錯題本、幹部修題。牌桌存（`shared/quiz.ts`，橋館 `src/lib/quizRecords.ts` 對應、parity 檢查）：
  - **成績**（e6-t04）：練完一次存一筆 `quizlog:<userId>:<時間>-<id>`（制度集、每題 id／特約／對錯，一次最多 50 題），每人只留最新 100 次；`GET/POST/DELETE /api/book/quiz/rounds`，只有本人。**保守做法**：登入時只存帳號；未登入只存這台瀏覽器（`tku-bridgebook:quizRounds`，try/catch，存不了照樣顯示），兩邊不合併——共用電腦上的紀錄不會算到下一個登入的人頭上。
  - **成績與錯題本**（e6-t05，`/practice/scores`）：總答對率、各特約答對率（低的在前，依特約弱點）、錯題本（每題最後一次答錯就留著、答對移出）、最近 10 次、清除全部。練習頁的「出題範圍」可選「只練錯題」（`?wrong=1`），仍可再依特約、程度篩。
  - **修題**（e6-t06，`/practice/fixes`，bookEdit）：存 `book:quizfix:<題目 id>`（在 `book` 前綴下，跟著每日備份；PRD 原寫 `quizfix:<id>`）。自動題可停用、改正解、改其他選項；修正附 `basis`（修正當時的叫品與正解），**原文改了修正就不套用**，修題頁標「目前不套用」要幹部重新確認。手動出題 id 是 `slug/sectionId/m-<亂數>`，可為意義題或叫品題（含 `hand`，答案與選項是叫品）；**只在出題時的制度集出現**（其他制度集可能改過那一段），段落不見了就不出。讀修題不需登入（練習頁要用），寫審計 `quiz:fix`／`quiz:unfix`。練習頁答完時，幹部看得到「修這題」。修題頁不建議任何內容：每個字都是幹部自己打的（硬性規則 1）。

## 風險與對策

- **自動題品質差**（意義太長、選項明顯）：干擾項取同表、長度相近；幹部停用壞題；統計每題答對率，太高或太低的標出來。
- **題庫格式牌桌還沒定**：先做橋譜自己的格式，轉換層獨立；牌桌定稿後只改轉換層。
