## 背景

社團的討論現在發生在 Facebook 社團與 LINE 群：發一副牌要用全形空格排四家牌，叫牌過程只能一行一行打，過兩天就被洗掉。淡江牌桌的 PRD（E13）早就提了「對橋牌友善的論壇」，但牌桌那邊排在 M2 公開版之後。**決定（2026-10-24）：論壇先在橋譜做，給社內社員測試；好用再把資料模型與元件搬到牌桌，開放全台灣橋手。** 橋譜的首頁也要有「社團新聞」欄位（第一版視覺稿就有，之後的展示頁漏掉了）。

兩站共用帳號與同一個 Worker（Durable Object），所以個人檔案與頭像做一次兩邊都能用；牌桌 E1 的 `e1-t15`～`t18`、`e1-t34`（個人檔案、預設頭像、上傳頭像）由本 epic 在 Worker 端完成，牌桌只接前端。

## 目標

- **個人檔案與頭像**：顯示名稱、頭像（上傳到 R2，裁成方形，有預設字首頭像）、自我介紹、常用制度、隊伍與搭檔；兩站共用。
- **板面**：社團公告（幹部發、置頂、首頁「社團新聞」讀這裡）、牌局討論、制度問答、閒聊；板面可由管理員增改。
- **貼文**：像 Facebook 的動態牆：文字、圖片，加上橋牌專用區塊：**四家牌（牌例）**、**叫牌過程**、**單手牌**、**特約引用**（連到橋譜段落）、**牌桌紀錄引用**（之後接牌桌）。寫牌例不用再對齊空格。
- **留言與反應**：巢狀一層的留言（留言也能放叫牌過程與單手牌）、表情反應（👍 ♠ ♥ ♦ ♣ 五種）、提到某人 `@`。
- **通知**：被回覆、被提到、公告發布，走牌桌通知中心（已上線）。
- **管理**：編輯、刪除自己的；幹部置頂、鎖定、刪除、檢舉處理；審計。
- **首頁**：社團新聞（公告板最新三則，置頂優先）＋最新討論三則。
- **搬得走**：資料模型與元件以牌桌 E13 的規格為準（`TKU-BridgeTable/docs/PRD/e13-community-forum.md`），將來搬到牌桌不重寫。

## 非目標

- 不做即時聊天、私訊（牌桌 E1 `e1-t25`～`t27`）。
- 不做公開匿名瀏覽：M1 只有登入社員可看可發；公開與多社團留給牌桌 E13／E12。
- 不做演算法推薦；時間序加置頂即可。
- 不做影片上傳；貼外部連結。

## 需求

### 功能

- **個人檔案**（Worker `StoredUser.profile`，與牌桌共用）：`displayName`、`avatarKey?`（R2）、`bio`（≤ 300 字）、`systems?`、`level?`（自評，與牌桌同一套名稱）。預設頭像＝字首＋由帳號決定的顏色。上傳：JPG／PNG／WebP ≤ 2 MB，前端裁成 512×512。
- **板面** `Board { id, name, description, order, postPolicy: 'all' | 'officers'; pinnedPostIds }`；內建四個：公告（只有幹部能發）、牌局討論、制度問答、閒聊。
- **貼文** `Post { id, boardId, authorId, title?, blocks: PostBlock[], createdAt, editedAt?, pinned?, locked?, reactions: Record<Emoji, userId[]>, commentCount }`。
- **區塊** `PostBlock`：沿用橋譜 `Block`（`paragraph`、`rules`、`note`、`hand`、`responses`）再加：
  - `{ kind: 'deal'; deal: Deal; dealer; vul; caption? }`：四家牌（與牌桌 `shared/board.ts` 的 `Deal` 同型別；E5 的 `deal` 區塊共用同一個元件 `DealDiagram`）。
  - `{ kind: 'auction'; auction: Auction; caption? }`：叫牌過程（沿用 `AuctionTable`）。
  - `{ kind: 'image'; assetId; alt; caption? }`。
  - `{ kind: 'ref'; slug; sectionId? }`：特約引用，顯示該段的標題與第一段摘要，點了開橋譜。
  - `{ kind: 'record'; tableRecordId }`：牌桌紀錄引用（M1 先存 id 與連結；牌桌 `e13-t07` 做好後顯示牌例）。
- **編輯器**：發文框像 Facebook（頭像、「想分享什麼牌？」）；工具列：圖片、四家牌、叫牌過程、單手牌、引用特約。四家牌輸入用 52 張牌點選（與牌桌 E13 `e13-t05` 的四手牌編輯器同規格，橋譜先做，之後搬）；叫牌過程輸入用叫牌盒（與牌桌 `BiddingBox` 同樣的兩列式）。
- **留言** `Comment { id, postId, parentId?, authorId, blocks: (paragraph | auction | hand)[], createdAt, reactions }`，巢狀一層；`@名字` 提到（自動完成社員名單）。
- **列表**：板面頁（置頂在上、新→舊、分頁 20 則）；首頁「社團新聞」讀公告板、「最新討論」讀其他板；貼文頁含全部留言。
- **通知種類**（牌桌通知中心）：`forum:reply`、`forum:mention`、`forum:announcement`、`forum:pinned`。
- **管理**：作者可編輯／刪除自己的；幹部（`forumModerate` 權限，管理員預設有）可置頂、鎖定、刪除任何貼文與留言、處理檢舉；每個動作寫審計（E8 的 `audit:`）。
- **搜尋**：標題與文字區塊的全文（DO SQLite `LIKE`，M1 夠用；之後接 E10 索引）。

### 非功能

- 儲存：Durable Object 的 SQLite（已有 `Sql` 介面）：`posts`、`comments`、`reactions`、`boards`、`reports` 五張表；圖片與頭像在 R2 bucket `bridgebook-files`（E5 共用）。
- 內容長度：貼文 ≤ 20 個區塊、文字 ≤ 5,000 字、圖片 ≤ 6 張；留言 ≤ 1,000 字。
- 速率：每人每分鐘 ≤ 5 則貼文或留言；每日圖片上傳 ≤ 30 張。
- 可搬移：型別放牌桌 `shared/forum.ts`（新檔），兩邊對拍；Worker 模組 `worker/forum.ts` 不依賴橋譜專有的東西。
- 無障礙：牌例與叫牌過程有文字替代（已有 `Suit` 的中文 `aria-label`）；鍵盤可發文、留言、反應。

## 設計方向

- 版面見 `DESIGN-V2.md` §12：動態牆單欄（最寬 40rem），左側板面清單，右側「社團新聞」與「活躍的人」；手機單欄，底部工具列多一個「討論」入口（目錄、討論、搜尋、我的）。
- 貼文卡：頭像、名字、時間、板面標籤；內文區塊；反應列（五種）；留言數；展開留言。牌例置中、叫牌過程與單手牌靠左。
- 發文框：預設一行；點開展開工具列；四家牌輸入是 4×13 的點選面板（與牌桌同樣的花色順序 ♠♥♦♣）。
- 風格跟隨使用者的個人設定（E9 六種風格的 token），不另做一套。
