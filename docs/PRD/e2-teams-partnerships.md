## 背景

社團不是一個制度打到底：一個隊伍 4–6 人、社團好幾隊、同隊的不同 pair 也可能打不同的約定。E1 提供了制度集這個容器，E2 讓它有主人：隊伍（team）與搭檔（partnership）各自擁有一個制度集，成員才能改，網站可以「依隊伍看」「依搭檔看」。

帳號在牌桌（`TKU-BridgeTable` E1）；隊伍與搭檔也存在那裡，之後牌桌的雙桌隊制賽（牌桌 E8）可以直接用同一份隊伍資料。

## 目標

- 管理員或 `bookEdit` 建立隊伍、指定隊長；隊長管理隊員與隊內搭檔。
- 任兩位社員可以組成搭檔（一方邀請、一方接受）；一個人可以有多個搭檔。
- 每個隊伍、每對搭檔自動擁有一個制度集（繼承社團或隊伍）。
- 「隊伍頁」列出隊員、搭檔、各搭檔與隊伍制度集的差異；「搭檔頁」是這對的制度集入口與制度卡入口。
- 新搭檔可以從隊伍制度集或另一對搭檔「複製一份」開始。

## 非目標

- 隊伍報名比賽、賽程：不做。
- 牌桌的雙桌隊制賽流程：牌桌 E8，只共用資料。

## 需求

### 功能

- 資料（牌桌 Worker）：

  ```ts
  interface Team { id: string; name: string; captainId: string; memberIds: string[]; profileId: string; createdAt: number; archived?: boolean }
  interface Partnership { id: string; userIds: [string, string]; teamId?: string; profileId: string; createdAt: number; status: 'pending' | 'active' | 'ended' }
  ```

  實作（C2，#29／牌桌 #122）：隊伍型別叫 `ClubTeam`（牌桌的 `Team` 已是隊制賽的 A／B）；`Partnership` 多 `acceptedAt?`、`endedAt?`，`userIds` 是 `[邀請者, 受邀者]`，邀請期間 `profileId` 是空字串、接受時才開制度集；婉拒或收回的邀請直接刪掉。API 在 `/api/club/teams*`、`/api/club/pairs*`（ARCHITECTURE.md §3.1）。

- 權限：
  - 隊伍：建立＝管理員或 `bookEdit`；改名、加減隊員、指定新隊長、封存＝隊長（編輯者也可以，C2 起）；隊伍制度集＝隊長（可開給隊員）。
  - 搭檔：兩人都能改搭檔制度集；結束搭檔後制度集保留唯讀。
  - 閱讀：隊伍與搭檔的制度集預設全社團社員可看（備忘除外）；可設為「只有成員」。
  - 實作（C3，#3／牌桌 #132）：規則在牌桌 `worker/roles.ts` 的 `profileAccess`。編輯者與管理員什麼都能做（2026-10-25 角色規則）；隊伍制度集隊長能存、改可見範圍，隊長打開 `membersEdit` 後隊員也能存（不能改可見範圍），封存後唯讀；搭檔兩人現役時能存、改可見範圍，結束後唯讀；成員才看得到備忘與版本紀錄；`visibility: 'members'` 時母制度集讀不到的人子制度集也讀不到；編輯者以外的人不能改 `scope`、`parentId`。管理頁的「隊伍」面板另用新的 `GET /api/club/members`（只有 id 與帳號名稱）選隊員。
- 頁面：`/teams`（隊伍列表）、`/teams/:id`（隊伍頁）、`/pairs/:id`（搭檔頁）、我的帳號多一段「我的隊伍與搭檔」。
- 差異：隊伍頁列出每對搭檔相對隊伍制度集的覆寫數與不採用數，點進去是 E1 的比較頁；隊長可以按「建議統一」送通知給該搭檔（E8 通知）。
- 複製：新搭檔建立時選「從隊伍開始」或「從某對搭檔複製」（複製 `adopted` 與 `overrides`，備忘不複製）。
  實作（C4）：搭檔的制度集在接受邀請時才建立，所以選擇放在搭檔頁：剛組成（自己沒有採用與覆寫）時「從別處複製制度集」說明可以就這樣從隊伍開始（已繼承隊伍），或選一個看得到的隊伍或搭檔制度集複製；之後也能再複製（會先確認取代）。母制度集不列入來源。瀏覽器組好 `ProfileInput` 用 `PUT /api/book/profiles/:id` 存（名稱、層級、母制度集、可見範圍、備忘維持這對的），Worker 不需改動。

### 非功能

- 一個人最多 10 個現役搭檔；一隊最多 8 人。
- 所有權限檢查在 Worker；前端只決定顯示。

## 設計方向

- Worker 新模組 `worker/teams.ts`（存 `team:<id>`、`pair:<id>`、索引 `userteam:<userId>:<teamId>`、`userpair:<userId>:<pairId>`），API `/api/club/teams*`、`/api/club/pairs*`；邀請走牌桌通知中心（`notifications.notify`）。
- E1 的制度集權限改為：`profile.scope === 'team'` → 隊長或被授權的隊員；`'partnership'` → 兩位成員。
- 搭檔頁的頂部是「這對的制度」摘要：採用哪些特約、覆寫幾條、最後更新；下面三個入口：讀制度、比較、制度卡（E3）。
